# 决策：HUD 排版全无衬线单族（2026-11-09）

状态：生效

## 问题

用户反馈界面"AI 感太强"。
诊断后确认成因不在配色也不在布局，而在排版三件事叠加：

- 标题用 `Bahnschrift` / DIN 这类窄体无衬线，是科幻 HUD 的通用套路。
- 全篇 `text-transform: uppercase` 加 0.2em 以上字距。
- 数字、参数值、小标题一律等宽字体。

## 决策

- 全站单字体家族，无衬线，不含衬线回退。
- 标题：`Segoe UI Variable Display`，700 字重，字距 −0.016em。
- 正文与控件：`Segoe UI Variable Text`，400 / 600 字重。
- 数字用同族 + `tabular-nums`，靠字重分层，不用等宽。
- 等宽只保留给零件编号（01–13）。
- 全站字距收到 0.01–0.06em，无一处 `uppercase`。
- 装饰性英文小字（`EXPLODE VIEW` / `ASSEMBLE`）换成中文说明。

## 替代方案（强制）

- 只换 font-family、保留原字距与大写：试过，观感仍是"模板科幻面板"，未解决。
- 衬线标题 + 无衬线正文（Sitka Display + Segoe UI）：试过一轮。
  有笔画对比、去 AI 感有效，但与"现代软件界面"的定位不符，维护者选定全无衬线后替换。
- 内嵌开源字体保证跨平台一致：会引入 200–400 KB 字体文件，且 Segoe 有授权限制不可分发，未采用。
- 保留等宽字体做数字：等宽是"科技感"偷懒的直接来源，放弃。

## 影响

- 收益：层级改由字号、字重、颜色承担，不再靠字距和大写撑气势。
- 代价：依赖系统字体，Windows 之外观感有差异（macOS 回退到 `Segoe UI` → `Noto Sans SC` → 系统 sans）。
- 排版规范的事实来源是 `css/style.css` 顶部的 `--font` / `--display` / `--mono` 三个变量。
- 换字体只需改这三个变量，不要在具体选择器里写死字体名。
